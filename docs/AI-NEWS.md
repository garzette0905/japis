# Jaden AI NEWS

2026-10-03, Jaden AI SNS(X · Threads) 대신 메뉴에 올린 화면. 주소는 `/#/news`.
X는 유료 API, Threads는 타인 계정 조회에 Meta 앱 심사(`threads_profile_discovery`)가 필요해
공개 뉴스 피드로 방향을 바꿨다. SNS 코드·화면(`/#/sns`)과 API는 지우지 않고 그대로 두었다.

화면 권한은 예전 SNS 카드의 키 `sns`를 그대로 쓴다. 이미 준 권한·사용 기록이 그 키에 걸려 있어서다.
추가 시크릿·DB 마이그레이션은 없다. 스냅숏은 `SESSIONS` KV의 `news:snapshot` 한 키다.

## 데이터 출처 (모두 공개 RSS/Atom 또는 공개 API, 키 불필요)

| 출처 | 용도 |
| --- | --- |
| AI타임스 전체기사 RSS | 한국어 AI 기사. 사용자가 가장 많이 보는 매체라 대표 기사로 우선 |
| TechCrunch AI RSS | 영어 AI 기사. 우선 매체 |
| The Information Atom | 유료 매체. 피드에 공개된 앞부분만 쓰고 AI 관련 글만 남김. 우선 매체 |
| The Verge AI RSS | 보조 매체 |
| OpenAI · Google DeepMind · Google AI · Hugging Face 블로그 RSS | AI 기업 공식 발표 |
| Google 뉴스 검색 RSS (영어·한국어, 최근 1일) | 매체 수 집계와 검색 순위 신호. 링크는 Google 뉴스를 거쳐 언론사로 이동 |
| Hacker News (Algolia 검색 API) | 커뮤니티 점수(15점 이상) |

Anthropic 은 공식 RSS 가 없어 Google 뉴스로 들어온 보도로만 잡힌다.
VentureBeat 피드는 2026-10-03 확인 때 HTTP 429 로 막혀 넣지 않았다.

## 순위

언론사는 조회수를 공개하지 않으므로 **조회수 순위가 아니다**. 확보 가능한 신호로 추정한다.

1. 최근 36시간 기사를 모아, 제목 단어가 많이 겹치는 기사(같은 언어)를 한 이야기로 묶는다.
2. 이야기마다 점수 = 다룬 매체 수 + Google 뉴스 검색 순위 + Hacker News 점수(로그) + 출처 가중치 + 주요 기업·출시·투자 언급.
3. 가장 최근 기사 기준 14시간 반감기로 점수를 줄인다.
4. 대표 매체 하나가 4건을 넘지 않게 Top 10 을 고른다. 대표 기사는 AI타임스·TechCrunch·The Information → 공식 블로그 → 그 밖의 순.
5. 지난 스냅숏 순위와 비교해 ▲/▼/NEW 를 붙인다.

한국어·영어 같은 이야기는 묶이지 않는다(단어 비교라서). 묶기는 휴리스틱이라 가끔 다른 이야기가 합쳐지거나 갈라질 수 있다.

영어 기사의 한국어 제목·한 줄 요약은 Workers AI(`@cf/zai-org/glm-4.7-flash`)가 제목과 공개 요약만으로 만든다.
실패하거나 한도를 넘기면 원문 제목만 보여준다.

## 갱신

- `wrangler.toml` 의 cron `3 * * * *`(매시 3분)이 스냅숏을 새로 만든다. 하루 정리 cron 과는 `event.cron` 으로 나뉜다.
- 화면을 열 때 스냅숏이 없으면 바로 만들고, 65분보다 오래됐으면 저장본을 먼저 주고 뒤에서 갱신한다.
- 새로고침 버튼은 10분이 지난 스냅숏일 때만 다시 수집한다(외부 피드에 부담을 주지 않도록).
- 모든 출처가 실패해 Top 10 이 비면 이전 스냅숏을 덮어쓰지 않는다.

## 대시보드 (2026-10-03)

대시보드 순서: **AI 뉴스 Top 10**(같은 `/api/news`·같은 카드) → 입력칸 · 메일·할 일·일정 → **오늘의 Muse 요약**.
화면 바로가기 타일(개인서비스 이하)은 대시보드에서 뺐다(상단 메뉴에 같은 목록이 있다).
공유화면 목록은 `내 계정`으로 옮겼다.

### 오늘의 Muse 요약

`GET /api/wiki/briefing`(Jaden Memo 권한)이 내 메모 중 **최근 3일 안에 고친** 것으로,
폴더 이름에 `Muse`가 들었거나 제목이 `데일리 브리핑`으로 시작하는 가장 새 메모 하나를 준다.
본문은 메모 저장 때 씻은 html 이고 내보낼 때 한 번 더 씻는다. 지금은 사람이 붙여 넣으면 된다.
Muse 가 직접 넣으려면 아래 중 하나가 필요하다(아직 만들지 않음).

- Muse 가 HTTP 요청을 보낼 수 있으면: 토큰 하나(`MUSE_TOKEN` 시크릿)로만 열리는 `POST /api/muse/briefing` 을 두고 Muse 폴더에 메모로 저장.
- Muse 가 메일만 보낼 수 있으면: 브리핑을 JAPIS 에 연결된 Gmail 로도 보내게 하고, JAPIS 가 이미 쓰는 Gmail 연결로 제목 `데일리 브리핑` 메일을 읽어 보여준다.

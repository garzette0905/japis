# JAPIS

**J**aden's **A**utomated **P**ersonal **I**ntelligence **S**ervice — 흩어져 있는 개인 서비스를
한자리에서 여는 개인 전용 포털입니다. (기획 배경은 [docs/CONCEPT.md](docs/CONCEPT.md) 참고)

wepic·가계부와 **같은 얼개**입니다: Cloudflare Worker 하나가 백엔드 전부이고, 프론트엔드는
`web/public` 을 정적 자산으로 그대로 서빙합니다. 빌드 단계가 없습니다.

## 구성

| 폴더 · 파일 | 내용 |
|---|---|
| `web/public/` | 화면 (HTML·CSS·JS) — Worker의 정적 자산으로 그대로 서빙 |
| `cloudflare/index.js` | 백엔드 Worker — 인증·권한·잠금해제·관리자 API |
| `cloudflare/services.js` | **화면(서비스) 목록. 화면을 늘릴 때 고치는 유일한 파일** |
| `cloudflare/wiki.js` | Jaden wiki(포털 안 메모) API — 목록·검색·사진·html 넣고 빼기 |
| `schema.sql` | 사용자·화면권한·접속기록 (D1) 스키마 |
| `migrations/` | 이미 운영 중인 D1에 표·컬럼을 더하는 스크립트(한 번씩 실행) |
| `docs/` | 기획 노트 |
| `wrangler.toml` | Cloudflare 설정 (D1·KV·크론·도메인) |

## 이 포털이 지키는 세 가지

1. **첫 화면은 로그인뿐입니다.** 어떤 주소로 들어와도(`/admin` 을 직접 쳐도) 서버는 빈
   껍데기 HTML만 내보냅니다. 메뉴·서비스 목록은 로그인한 뒤 API로만 받으므로, 로그인
   전에는 페이지 소스를 뒤져도 **어떤 화면이 있는지조차** 알 수 없습니다.
2. **주소는 서버만 압니다.** 서비스의 실제 주소는 응답에 담기지 않습니다. `/go/<key>`
   가 302로만 알려줍니다(오른쪽 프레임의 `src` 도 `/go/<key>` 입니다 — 302는 프레임이
   알아서 따라갑니다).
3. **가입이 없습니다.** 관리자가 사람을 만들고, 그 사람이 볼 화면을 골라 줍니다.

> 예전에는 화면을 열 때마다 비밀번호를 한 번 더 받았습니다(재인증). **지금은 꺼져
> 있습니다** — 이미 로그인해 들어온 사람에게 링크 하나 누를 때마다 또 묻는 것은,
> 보태는 안전보다 깎아먹는 쓸모가 컸습니다. 장치는 그대로 남아 있으니 특별히 가려야
> 할 화면이 생기면 **관리 → 화면 권한**에서 그 줄만 다시 켜면 됩니다.

## 화면 얼개

```
┌───────────────────────────────────────────────────────────┐
│ JAPIS   9월 13일 (토)  14:32  ☀️ 21°          Jaden  내 계정 │  ← 상단 띠: '지금'
├───────────┬───────────────────────────────────────────────┤
│ ⌂ 대시보드 │  좋은 오후입니다, Jaden님                       │
│           │                                               │
│ 개인서비스 6│  오늘                                          │
│  ▣ wepic ↗│  ┌ 메일 ──┐ ┌ 할일 ──┐ ┌ 일정 ──┐   ← 셋이 같은 키 │
│  ▤ 가계부  │  │ 10줄   │ │ 10줄   │ │ 10줄   │   한 줄 = 그 항목 │
│  …        │  └────────┘ └────────┘ └────────┘              │
│ 협업     6 │  개인서비스                                     │
│  ✉ 구글메일│  [타일] [타일] [타일] [타일]                     │
└───────────┴───────────────────────────────────────────────┘

화면 하나를 누르면 — 본문을 **덮는다**
┌───────────┬───────────────────────────────────────────────┐
│ ⌂ 대시보드 │ ▣ wepic                              ⟳  ↗  ✕ │
│ 개인서비스 6│ ┌───────────────────────────────────────────┐ │
│  ▣ wepic  │ │                                           │ │
│  …        │ │            (열어 둔 화면)                   │ │
└───────────┴─┴───────────────────────────────────────────┴─┘
   ↑ 기둥은 그대로 있다                ↑ 본문은 이 아래에 그대로 있다
```

- **상단 띠**에는 메뉴를 두지 않습니다. 날짜·시간·날씨(`/api/weather`)와 계정만 둡니다.
  날씨는 키가 필요 없는 [Open-Meteo](https://open-meteo.com) 를 Worker가 대신 물어보고
  KV에 10분 담아 둡니다(브라우저가 바깥 서버에 직접 말하지 않습니다). 위치는
  `wrangler.toml` 의 `WEATHER_LAT` · `WEATHER_LON` · `WEATHER_PLACE` 로 바꿉니다.
- **왼쪽 기둥**이 화면 목록입니다. 묶음마다 개수를 달고, 한 줄은 `[픽토그램] 이름`,
  손이 닿으면 오른쪽에 `↗` 가 나옵니다. 지금 보고 있는 줄은 **통째로 검게** 뒤집힙니다.
  좁은 화면에서는 접히고 `☰` 로 밀어 넣습니다.
- **대시보드는 한 화면에 들어옵니다.** 화면 목록은 설명 없이 **이름만 남긴 타일**로
  깝니다 — 대시보드는 둘러보는 곳이 아니라 고르는 곳이라서입니다. 설명·계정·저장소
  같은 나머지는 묶음 화면(`#/g/<key>`)의 카드가 맡습니다.
- **대시보드 맨 위의 '오늘'** 에는 **안 읽은 메일 · 남은 할 일 · 다가오는 일정**이
  이 순서로, 기본으로 펼쳐져 있습니다(아침에 먼저 보는 것부터 왼쪽). 구글 화면을
  `<iframe>` 에 끼울 수는 없습니다 — mail.google.com · calendar.google.com 은
  `X-Frame-Options: DENY` 로 내려와 어느 사이트에서도 프레임에 담기지 않습니다(구글
  정책이라 우리 쪽에서 풀 수 없습니다). 그래서 화면을 빌려오는 대신 **내용을 받아 와
  우리 글자로 그립니다**(`/api/feed`). 본문은 내려오지 않습니다.
- 세 칸은 **같은 키로 섭니다.** 안에 든 항목 수가 달라도 바닥이 한 줄로 맞아야 눈이
  세 번 다시 자리를 잡지 않습니다. 각 칸에 **열 개**가 들어오고(`FEED_MAX`), 열 줄이
  굴리지 않고 그대로 보이는 높이로 잡아 두었습니다(`--today-rows` · `--today-row`).
- **한 줄이 곧 그 항목으로 가는 문입니다.** 메일은 그 대화, 일정은 그 일정, 할 일은 그
  할 일로 바로 나갑니다(서버가 항목마다 주소를 실어 보냅니다). 주소가 없는 항목은 그
  화면 자체를 여는 단추가 됩니다 — **눌리지 않는 줄은 없습니다.**

## 화면을 여는 두 가지 길

| | 어디서 | 무엇이 열리나 |
|---|---|---|
| 이름·카드를 누른다 | 왼쪽 기둥 · 카드 | **본문을 덮는 화면** — 포털을 떠나지 않고 그 자리에서 |
| `↗` 를 누른다 | 왼쪽 기둥 · 카드 오른쪽 위 | **새 탭** |

어느 쪽으로 열리는지는 **누르기 전에 보입니다** — 카드에 `이 자리에서` / `새 탭`
이라고 적히고, 왼쪽 기둥에서 새 탭으로만 열리는 줄은 `↗` 가 늘 떠 있습니다.

> 예전에는 이것이 **오른쪽 칸**이었습니다. 그러면 기둥·본문·화면 셋이 한 줄에 서는데,
> 셋 중 어느 것도 제 폭을 갖지 못합니다 — 특히 메모(Jaden wiki)는 글을 읽고 쓰는
> 자리라 좁아지는 순간 쓸모가 반으로 줍니다. 그래서 **자리를 나눠 갖지 않고 덮습니다.**
> 기둥은 그대로 남아 다음 화면으로 바로 건너뛸 수 있고, `✕` 를 누르거나 다른 줄을
> 고르면 덮개가 걷히면서 본문이 그대로 돌아옵니다.

| 화면 | 누르면 | 왜 |
|---|---|---|
| wepic · 가계부 · Taylor Bookshelf · Julie | 덮개 화면 | 막는 헤더가 없다 |
| **구글 캘린더 · 구글 할일** | 덮개 화면 | 본 화면 대신 **임베드 주소**(`frameUrl`)를 쓴다 |
| 카드모아 | 새 탭 | 그쪽이 `frame-ancestors 'none'` 을 내보낸다 — **내 저장소라 고칠 수 있다** |
| 구글 포토 · 구글 메일 · 네이버 메모 · OneDrive | 새 탭 | 제공자가 막는다. 임베드 주소도 없다 |
| Jaden wiki · SNS | 포털 안 화면 | 프레임을 쓸 일이 없다 — 그냥 그 화면으로 넘어간다 |

프레임을 막아 둔 사이트는 눌러도 **곧바로 새 탭**으로 나갑니다.
막혔는지는 서버가 한 번 열어 보고 헤더(`X-Frame-Options` · `frame-ancestors`)로 판단해
KV에 하루 담아 둡니다(`/api/frameable`). 브라우저는 프레임이 막혔다는 것을
자바스크립트에 알려주지 않고, 누른 뒤에 물어보면 그 사이 클릭이 끊겨 새 탭이 팝업
차단에 걸리기 때문에 **미리** 알아 둡니다.

덮개가 열려 있는 동안 본문은 그리지 않습니다 — 뒤에 살아 있으면 스크롤이 두 겹이 되고,
화면 낭독기도 보이지 않는 글을 읽습니다. 좁은 화면에서는 기둥까지 덮습니다.

> 내 사이트인데 프레임에 안 담긴다면 그쪽에서 막고 있는 것입니다. 예를 들어
> **카드모아**는 `frame-ancestors 'none'` 과 `X-Frame-Options: DENY` 를 내보냅니다 —
> 그 저장소에서 JAPIS 주소를 허용(`frame-ancestors https://japis.…`)하면 프레임에서
> 열립니다.

### 프레임에서만 쓰는 다른 주소 (`frameUrl`)

본 화면은 프레임을 막아 두었지만 "붙여 쓰라고" 따로 내주는 주소가 있는 곳이 있습니다.
그런 곳은 `services.js` 에 `frameUrl` 을 적어 둡니다. 프레임은 `/go/<key>?in=frame` 으로
부르고 서버가 그때만 이 주소로 보냅니다 — `↗`(새 탭)는 언제나 본래 `url` 로 나갑니다.
**프레임은 보기용, 새 탭은 쓰기용**입니다.

지금 쓰는 곳은 둘입니다.

| 화면 | 프레임에서 여는 주소 |
|---|---|
| 구글 캘린더 | `calendar.google.com/calendar/embed` (`mode=AGENDA` — `MONTH`·`WEEK` 로 바꿀 수 있습니다) |
| 구글 할일 | `tasks.google.com/embed/list/~default` |

구글 할일에는 `frame: true` 를 같이 적어 두었습니다. 로그인해야 보이는 임베드라, 서버가
로그인하지 않은 채로 두드리면 **구글 로그인 화면(`X-Frame-Options: DENY`)** 을 보고
"막혔다"고 잘못 판단하기 때문입니다. `frame: true` 는 "조사하지 말고 담아라"입니다 —
실제 브라우저에서 빈 칸이 뜬다면 그 줄을 지우면 새 탭으로 돌아갑니다.

> 브라우저가 서드파티 쿠키를 막아 두면 임베드가 캘린더 대신 구글 로그인 화면을
> 보여줄 수 있습니다. 그때는 `↗` 로 새 탭에서 열면 됩니다.

## 생체인증 (휴대폰 지문·얼굴)

들어올 때와 잠긴 화면을 열 때, 비밀번호 대신 **지문·얼굴**을 쓸 수 있습니다. 비밀번호를
없애는 것이 아니라 나란히 둔 두 번째 길입니다.

- **등록**: 로그인한 뒤 **내 계정 → 생체인증 → 이 기기 등록** (현재 비밀번호를 한 번 더
  받습니다 — 세션만 훔친 사람이 자기 지문을 몰래 심지 못하게).
- **로그인**: 로그인 화면의 *생체인증으로 로그인*. 이메일을 묻지 않습니다.
- **화면 열기**: 잠금 모달에 *생체인증으로 열기* 가 먼저 뜹니다.

지문 자체는 기기 밖으로 나오지 않습니다. 포털에 남는 것은 확인용 **공개키뿐**이라 이
저장소가 통째로 새어도 남의 계정으로 들어갈 재료가 되지 않습니다. 열쇠는 **등록한
주소에만** 매입니다(`*.workers.dev` 에서 만든 것은 운영 도메인에서 쓰이지 않습니다).

## 최초 로그인

1. 배포 후 `https://<주소>/` 로 들어갑니다.
2. 이메일에 **`garzette@paran.com`**, 비밀번호는 **비워 두고** 로그인합니다.
   (users 표가 비어 있으면 이 계정이 비밀번호 없이 자동으로 만들어집니다)
3. 곧바로 비밀번호 설정 화면이 뜹니다. 여기서 정한 비밀번호가 저장되는 순간
   **비밀번호 없는 로그인 문은 스스로 닫힙니다.**
4. 상단 **관리** 메뉴에서 사용자를 만들고 화면 권한을 골라 줍니다.

> ⚠️ 2번과 3번 사이에는 이메일만 알면 누구나 들어올 수 있습니다. 배포 직후 바로
> 마치세요. 다른 이메일로 시작하려면 `ADMIN_EMAIL` 시크릿을 먼저 등록하면 됩니다.

## 화면 하나 더 붙이기

[`cloudflare/services.js`](cloudflare/services.js) 의 `SERVICES` 배열에 한 덩어리를 더하고
push하면 끝입니다. DB 마이그레이션이 필요 없습니다.

```js
{
  key: 'newthing',            // 한 번 정하면 바꾸지 않는다(권한표가 이 값으로 붙는다)
  label: '새 서비스',
  group: 'service',           // home | service | tool | connect
  desc: '한 줄 설명',
  url: 'https://example.com', // null 이면 카드에 '준비중'으로 뜨고 열리지 않는다
  repo: 'garzette0905/newthing',
  accent: 'teal',             // 카드 머리띠 색(장식 전용)
  icon: '✨',
  reauth: false,              // 들어갈 때 비밀번호를 한 번 더 받을지(지금은 모두 false)
  external: true,             // 다른 사이트로 나가면 true
  // frame: false,            // 제공자가 프레임을 막는 것이 확실하면 적어 둔다
  //                          // (적지 않으면 서버가 한 번 열어 보고 판단한다)
}
```

새 화면은 기본적으로 **아무에게도 보이지 않습니다**(관리자 제외). 관리 → 화면 권한에서
사람마다 켜 주세요.

## Jaden wiki (포털 안 메모)

네이버 메모가 하던 일을 포털 안에서 합니다. 네이버는 메모 API를 열지 않아 링크로는
거기까지였습니다 — 메모가 우리 D1에 있으면 목록·검색·미리보기가 전부 우리 것이 됩니다.

| 화면 | 주소 | 하는 일 |
|---|---|---|
| 대시보드 | `#/wiki` | 폴더·전체·중요·휴지통, 검색, 정렬(수정일·생성일·오래된순·제목), 카드/목록 보기 |
| 편집기 | `#/wiki/<번호>` · `#/wiki/new` | 서식 있는 본문, 사진, html·md 넣고 빼기, 공유 |
| 공유된 메모 | `/s/<이름표>` | **로그인 없이** 열리는 그 메모 한 장 (아래 *공유* 참고) |

편집기에 있는 것 — 실행취소·다시실행, 문단 모양(본문·제목 1~3), 글자 크기, 굵게·기울임·
밑줄·취소선, 글자색·형광펜, 글머리·번호·**체크리스트**, 들여쓰기, 정렬, 인용·코드·구분선·
**표**, 링크(Ctrl+K), **사진**, 서식 지우기. 2초마다 **저절로 저장**되고 `Ctrl+S` 로
바로 저장합니다.

### 한 메모의 세 얼굴 — 편집 · HTML · 보기

편집기 머리에 얼굴을 바꾸는 알약 셋이 있습니다.

| | 무엇인가 |
|---|---|
| **편집** | 서식 단추가 달린 평소의 편집칸 |
| **HTML** | **태그를 직접 적는 칸.** 다른 데서 만든 조각을 그대로 붙여 넣거나, 편집칸이 만들어 준 것을 손볼 때 |
| **보기** | 저장했을 때 **남들이 보게 될 그 모습.** 단추도 손잡이도 없습니다 |

HTML 칸에서 나올 때 적은 것을 **한 번 씻어서** 편집칸에 옮깁니다. 저장할 때 서버가
어차피 다시 씻지만, 씻지 않은 것이 편집칸에 들어가면 그 순간부터 **이 페이지 안에서
살아 있는 것**이 되기 때문입니다 — `<img onerror=…>` 한 줄은 저장을 기다려 주지
않습니다. 그래서 화면 쪽에도 같은 흰 목록을 한 벌 둡니다
([`web/public/wiki.js`](web/public/wiki.js) 의 `safeHtml` — 브라우저에는 진짜 파서
(`DOMParser`)가 있어 정규식 대신 문서를 만들어 걸러냅니다).

- **사진** — 단추·붙여넣기(Ctrl+V)·끌어다 놓기 셋 다 됩니다. 파일은 R2(`japis-wiki`)에
  들어가고 본문에는 `/api/wiki/files/<id>` 만 적힙니다. 그 주소는 **로그인해야** 열리고,
  이름이 `<사용자번호>/…` 로 시작해 남의 사진은 잡히지 않습니다.
- **사진 크기** — 사진을 한 번 누르면 네 귀퉁이에 손잡이가 붙고 위에 *작게 · 중간 · 크게 ·
  원본* 단추가 뜹니다. 귀퉁이를 끌어도 되고(마우스·손가락 둘 다), 단추 한 번으로 끝내도
  됩니다. 크기는 `<img width="…">` 로 적혀 html 로 내보낸 파일에서도 그대로 유지됩니다.
- **html 저장** — 메모 하나를 그대로 열리는 `.html` 파일로 내려받습니다. 본문의 사진은
  `data:` 로 **심어서** 내보내므로 파일 하나만 들고 나가도 그림이 따라갑니다.
- **html · md 불러오기** — 목록의 *불러오기* 는 파일마다 새 메모를 만들고(한 번에
  20개까지), 편집기의 *html · md 열기* 는 지금 보고 있는 메모에 덧붙입니다.

### .md 는 모양 그대로 들어옵니다

`.md` 파일을 그냥 넣으면 `##` · `|---|` 같은 기호가 글자로 남아 읽을 수가 없습니다.
그래서 **들여오는 그 자리에서 html 로 바꿉니다**([`cloudflare/wiki.js`](cloudflare/wiki.js)
의 `mdToHtml`) — 표는 표로, 그림은 그림으로 섭니다.

| 마크다운 | 어떻게 서는가 |
|---|---|
| `# ~ ######` | 제목 1~6 |
| `\|a\|b\|` + `\|---\|---\|` | **진짜 표** (`<table>` — 칸선·머리줄까지) |
| `![alt](주소)` · `[글](주소)` | 그림 · 링크 |
| `- ` · `1. ` · 들여쓴 줄 | 글머리 · 번호 · **안쪽 목록** |
| `- [x]` · `- [ ]` | 편집기가 쓰는 것과 같은 **체크리스트 네모칸** |
| ` ```…``` ` · `` `…` `` | 코드 덩어리 · 코드 조각 |
| `> ` · `---` · `**굵게**` · `*기울임*` · `~~취소~~` | 인용 · 구분선 · 글자 꾸밈 |

변환기는 **서버 한 곳에만** 둡니다. 편집기가 `.md` 를 열 때도 그 파일을
`/api/wiki/render` 로 보내 html 로 바꿔 받습니다 — 브라우저에 한 벌 더 두면 둘이 곧
어긋나기 때문입니다. 바뀐 html 도 예외 없이 `sanitizeHtml()` 을 한 번 더 지납니다.

### 공유 — 메모 하나를 주소 하나로

편집기의 **공유** 를 켜면 그 메모만 담긴 주소가 하나 생깁니다. 그 주소를 아는 사람은
**로그인하지 않아도** 그 메모 한 장을 봅니다. 포털의 다른 화면은 열리지 않습니다.

- **주소에 메모 번호가 들어가지 않습니다.** `/s/3` 이라면 `/s/4` 를 눌러 남의 메모로
  건너갈 수 있습니다. 대신 128비트(32자 hex) **무작위 이름표**를 뽑아 `/s/<이름표>` 로
  둡니다 — 찍어서 맞힐 수 있는 수가 아닙니다.
- **끄면 그 자리에서 죽습니다.** 이름표를 지우므로 돌던 주소는 바로 열리지 않고,
  다시 켜면 **새 이름표**가 나옵니다(한 번 거둔 주소는 되살아나지 않습니다).
- **휴지통에 든 메모는 열리지 않습니다.** 지운 것이 주소로 계속 보이면 지운 것이
  아닙니다.
- 공유 화면은 포털 껍데기를 주지 않습니다. 그 메모만 담은 html 한 장을 그 자리에서
  만들어 보내고, 본문의 사진은 로그인해야 열리는 주소라 `data:` 로 **심어서** 보냅니다.
  `noindex` · `no-store` · 스크립트를 막는 `Content-Security-Policy` 가 함께 나갑니다.
- **폴더 차례** — 왼쪽 폴더 줄에 손이 닿으면 왼쪽에 손잡이(⣿)가 나옵니다. 잡고 끌면
  차례가 바뀌고, 손을 떼는 순간 저장됩니다. 손잡이에 손을 얹고 `↑` · `↓` 로도 옮길 수
  있습니다 — 끌어다 놓기만 두면 그것을 못 쓰는 사람에게서 기능을 빼앗는 셈입니다.
  줄 아무 데나 잡게 하지 않은 이유는 "폴더를 열려고 눌렀는데 끌려 나왔다"를 막기
  위해서입니다 — **여는 자리와 옮기는 자리를 따로 둡니다.**
- **폴더 목록만 굴러갑니다.** 기둥을 화면 높이에 묶어 두고 그 안에서 가운데(폴더)만
  굴립니다. '메모 쓰기'는 늘 위에, '휴지통'은 늘 아래에 붙어 있습니다.
- **#태그** — 본문에 적은 `#낱말` 을 뽑아 두고 검색이 함께 훑습니다.
- **지운 메모는 휴지통으로** 갑니다. 거기서 한 번 더 눌러야 진짜로 사라집니다.

### 휴대폰에서도 그대로 씁니다

읽기만이 아니라 **쓰고 고치는 것까지** 됩니다. 좁은 화면에서 걸리는 세 가지를 각각
손봤습니다.

| 걸리는 것 | 한 일 |
|---|---|
| 마우스가 없어 `hover` 로 숨겨 둔 단추가 영영 안 나온다 | `@media (hover: none)` 에서 카드의 별표·휴지통, 폴더의 `⋯` 를 늘 보이게. 손잡이도 손가락 크기로 키웁니다 |
| 서식 단추 25개가 줄바꿈하면 화면 절반을 먹는다 | 서식 줄을 **한 줄로 두고 옆으로 밀어** 봅니다(휴대폰 편집기들이 하는 방식) |
| iOS 는 글씨가 16px 보다 작은 입력칸을 누르면 화면을 확대해 버린다 | 입력칸 글씨를 16px 아래로 내리지 않습니다. `user-scalable=no` 로 막지 않습니다 — 손가락으로 넓혀 보는 것까지 빼앗을 이유는 없습니다 |

이 밖에 편집기 머리의 글자 이름표를 걷어 아이콘만 남기고(가장 자주 누르는 *저장* 만
글자로 둡니다), 카드는 한 칸씩 세우고, 표는 본문을 밀지 않고 표만 옆으로 밀립니다.

### 본문은 서버가 씻어서 저장합니다

편집기가 만든 것이든 불러온 파일이든, 저장하는 길목에서 흰 목록에 없는 태그·속성을
지웁니다([`cloudflare/wiki.js`](cloudflare/wiki.js) 의 `sanitizeHtml`). `<script>`·
`onerror=`·`javascript:` 는 들어오지 못하고, 링크에는 `rel="noopener noreferrer"` 가
붙습니다. 화면에서 거르지 않고 **저장 전에** 거르는 이유는, 한 번 들어온 것이 다음에
목록을 그릴 때·내보낸 파일을 열 때 또 살아나기 때문입니다.

문은 다른 화면과 같은 `jadenwiki` 권한 하나입니다 — 관리 → 화면 권한에서 그 줄을 끄면
메뉴에서 사라지는 **동시에** API도 닫힙니다.

## 협업 카드의 최근 항목

협업 묶음의 카드는 **최근 것 몇 개를 앞면에 얹습니다** — 안 읽은 메일 제목, 다가오는
일정, 최근 사진 썸네일, 최근에 연 문서. 브라우저가 구글·마이크로소프트에 직접 말하지
않고 Worker가 대신 물어본 뒤 제목과 시각만 추려서 보냅니다.

- 잠긴 화면은 **잠금을 푼 뒤에만** 내용이 보입니다(메일 제목은 그 화면의 내용이지
  목차가 아닙니다).
- 구글 포토·메일·캘린더는 **연결 하나를 나눠 씁니다** — 한 번 동의하면 셋 다 열립니다.
- Refresh Token 은 AES-GCM 으로 싸서 D1에 둡니다(열쇠는 `SESSION_SECRET` 에서 뽑습니다).

켜려면 제공자 키를 시크릿으로 등록해야 합니다 —
[cloudflare/README.md](cloudflare/README.md) 3번 참고. 등록 전에는 카드에 *연동 설정 전*
이라고만 뜨고 포털의 다른 기능에는 영향이 없습니다.

## 로컬 실행

```bash
npm install
cp .dev.vars.example .dev.vars   # SESSION_SECRET 을 아무 긴 문자열로 채운다
npm run db:local                 # 로컬 D1에 표 생성 (최초 1회)
npm run dev                      # wrangler dev — 기본 http://localhost:8787
```

## 배포

**Cloudflare Workers** — `main` 에 push하면 자동 배포됩니다. 설정 절차(D1·KV·시크릿)는
[cloudflare/README.md](cloudflare/README.md) 참고.

> ⚠️ `migrations/` 에 새 파일이 생겼다면 **push하기 전에** 운영 D1에도 한 번 적용해야
> 합니다. 새 코드가 읽을 표가 배포 시점에 이미 있어야 오류가 나지 않습니다.

## 화면 디자인

나이키 커머스의 결을 따릅니다 — **글자와 여백이 말하고, 장식은 입을 다뭅니다.**

- **색은 셋뿐입니다.** 검정 `#111111` · 흰색 `#ffffff` · 회색 `#f5f5f5` 가 화면의 95%를
  덮습니다. 단추도 활성표시도 전부 검정입니다(예전의 파랑 `#0075de` 는 없앴습니다).
  빨강 `#d30005` 은 *지운다/위험*, 초록 `#007d48` 은 *연결됨* 에만 섭니다. 그 밖의
  색은 폴더 점처럼 **색이 곧 이름표**인 자리에만 남깁니다.
- **그림자가 없습니다.** 카드는 종이에서 뜨지 않고 그냥 놓입니다. 깊이를 내는 것은
  1px 실선 하나뿐입니다.
- **모서리는 둘 중 하나입니다.** 담는 것(카드·칸·표)은 각지게 `0`, 누르는 것
  (단추·칩·검색칸)은 완전한 **알약**. 그 사이의 어정쩡한 8px 은 없습니다.
- **글자 위계가 극단적입니다.** 큰 제목(40px, 자간 −1.2px)과 작은 글자(12–16px) 사이에
  중간이 거의 없습니다 — 위는 간판, 아래는 목록. 묶음 이름은 11px 대문자로 눕힙니다.
- **글꼴** — `Inter`(라틴) + `Noto Sans KR`(한글), 간판 글씨(로고)만 `Bebas Neue`.

### 아이콘 — 속을 채운 한 벌

예전에는 📓 ✉️ 📅 같은 이모지를 그대로 썼습니다. 이모지는 기기마다 다른 그림이 뜨고,
저마다 색과 광택이 달라 나란히 세우면 줄이 서지 않습니다. 그래서 **한 벌로 그린
그림**으로 바꿨습니다([`web/public/icons.js`](web/public/icons.js)).

그 첫 판은 가는 선(1.75) 그림이었는데, 줄은 섰지만 힘이 없었습니다 — 16px 짜리
메뉴에서 선 그림은 흐릿한 얼룩처럼 보이고, 검은 알약 위에 얹으면 더 그렇습니다.
그래서 **속을 채운 그림**으로 다시 그렸습니다. 굵고 단순한 덩어리 하나가 가느다란
윤곽선 여럿보다 멀리서도 먼저 읽힙니다.

| | |
|---|---|
| **색을 품지 않는다** | `currentColor` 하나로 칠하므로 흰 바탕에서도, 검은 알약 안에서도 글자색을 그대로 따라 뒤집힙니다 |
| **24 칸 안에 산다** | 실제 그림은 2~22 사이에 두어 어느 그림이든 눈에 같은 크기로 보입니다 |
| **덩어리는 셋을 넘지 않는다** | 설명이 필요한 그림은 두지 않습니다 — 봉투는 봉투로, 달력은 달력으로 |
| **속을 파서 자세를 낸다** | 사진의 해, 카메라의 렌즈, 달력의 날짜칸은 선을 더 긋는 대신 덩어리에서 구멍을 팝니다(`fill-rule="evenodd"`) |

화면을 하나 더 붙였다면 `SERVICE_ICONS` 에 같은 key 로 그림을 하나 더합니다. 없으면
점 하나로 뜹니다 — 엉뚱한 그림이 붙는 것보다 낫습니다.

자세한 토큰은 [`web/public/styles.css`](web/public/styles.css) 맨 위에 있고, 토큰만으로
안 되는 것(알약이어야 하는 단추, 각져야 하는 카드)은 같은 파일 맨 아래의 *나이키 결*
묶음에 모아 두었습니다.
